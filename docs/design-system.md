## 1. Direction

**Quiet Scientific.** SeaBed Lens should feel like a beautiful scientific instrument: somewhere between a scientific
publication, modern software and a field instrument. It must not look like an AI-generated SaaS dashboard, a generic AI
product or an over-designed portfolio.

- The underwater imagery, model predictions and research findings provide the visual richness. The UI never competes
  with them.
- Hierarchy comes from typography, spacing and alignment before containers.
- At most three visible layers: **page background → content surface → emphasis**.
- **One strong accent:** ocean teal for brand and primary action. Amber is rare.
- Controls are obvious when needed and quiet otherwise.
- A visitor should think about *the organisms → the model → the result → the research*, and almost never about the UI.

**Preserve from earlier versions:** the interactive demo as the homepage hero; swipe comparison; detection and
segmentation visualisation; synchronized highlighting between image and class list; dark workspace for image work; light
reading surface for research content; claim-first findings; source lines under figures and tables; clear separation of
test / val / TTA; responsive layout; large touch targets; keyboard access; reduced-motion support; honest handling of
pending or unavailable results.

## 2. The design test

Ask before accepting any component or page:

1. Can I remove something without losing information or function? → remove it.
2. Does this need a card? → if whitespace or type can group it, no.
3. Is this label necessary? → if the context already says it, drop it.
4. Does it look like a generic AI dashboard? → simplify.
5. Does the interface compete with the imagery? → simplify.
6. Does the page still work with all decoration removed? → if yes, the hierarchy is sound.

**North star:** *Make SeaBed Lens look designed by a thoughtful human scientist with excellent taste, not generated by an
AI trying to demonstrate every modern UI pattern it knows.*

## 3. Anti-patterns (reject unless there is a strong functional reason)

| Family | Reject |
|---|---|
| Generic AI | purple/blue gradients, glowing borders, glassmorphism, gradient text, sparkle icons, futuristic copy |
| SaaS dashboard | card grids everywhere, giant metric tiles, badge clutter, nested cards, chrome around simple information |
| Design-system showcase | every component visibly demonstrating a token, excessive labels, excessive semantic colours, decorative geometry |
| Developer tool | monospace everywhere, terminal surfaces, too many technical IDs, tiny labels everywhere |
| Dated academic site | dense paragraphs, Times-like type, paper clutter, footnotes on every sentence, walls of technical text |
| Decoration | decorative gradients, glow, floating glass panels, blobs, illustrations that aren't data, heavy shadows |

## 4. Grounded in perception

The visual layer may change; these findings do not. If a later choice conflicts with one, the finding wins.

| Finding | Rule on SeaBed Lens |
|---|---|
| **Chromatic adaptation** — the eye adapts to the surround, so a tinted frame shifts perceived image colour (reason for ISO 3664's neutral surround) | The well behind every image is neutral grey `#17191B` (OKLCH chroma ≈ 0.005). Teal chrome stays one step further out. The teal action colour never appears inside the image. |
| **Positive polarity** — dark text on light is read more accurately (Piepenbrock et al., 2013) | Results, Explore and About are light by default. Try it and the Lab are dark, like a photo editor, because there the image is the content. |
| **Halation** — pure white on black blurs for readers with astigmatism | Dark-surface text is `#E9EFED`, never `#FFF`; light-surface text is `#17211F`, never black. |
| **Position is decoded best** (Cleveland & McGill, 1984) | Dot plots on one shared axis with direct labels. No pie, radar, 3D or truncated bars. |
| **Pre-attentive pop-out** (Treisman & Gelade, 1980) | Inside the image, hue means class and nothing else. Selection dims everything else. Teal marks the one primary action per view. |
| **Change blindness** (Simons & Rensink, 2005) | Compare in one place: swipe on Home, hold-to-flicker ground truth in Try it, swipe and difference views in the Lab. |
| **Working memory ≈ 4 chunks** (Cowan, 2001) | The Try it inspector shows count, threshold and the top three classes; everything else expands on request. The Lab caps comparisons at 4 variants. |
| **Fitts's law** | Targets ≥ 32 px with a pointer, ≥ 44 px on touch; controls low on phones. |
| **Response-time limits** — 0.1 s / 1 s / 10 s (Miller, 1968; Card et al., 1991) | Filters re-render in < 0.1 s without animation. Runs keep the old result dimmed and show the step and elapsed time. Past 10 s show an estimate. |
| **Peripheral motion captures attention** (Abrams & Christ, 2003) | Nothing moves unless the visitor caused it. Motion only reports a state change. |
| **Recognition over recall / Jakob's law** | About follows a paper's first page; Try it follows the canvas-plus-inspector layout of vision tools. |

## 5. Typography

Three typefaces, maximum.

| Role | Family | Use for | Never for |
|---|---|---|---|
| Interface / body | **Inter** (400, 500, 600) | navigation, body, buttons, controls, labels, tables, metadata, captions, numbers in tables (tabular figures) | — |
| Editorial display | **Source Serif 4** (400–600, optical sizes) | page titles, the homepage statement, claim headlines on Results, About title | buttons, labels, the Try it workspace |
| Data / technical | **JetBrains Mono** (400, 500) | run IDs, file names, model IDs, code, BibTeX | ordinary labels such as Source, Test, Dataset, Status, Updated |

Inter: enable `cv11` and `ss01` (single-storey a, open digits). Tables use `font-variant-numeric: tabular-nums`.

### 5.1 Scale (size / line height, px)

| Token | Size / LH | Family, weight | Typical use |
|---|---|---|---|
| `display` | 48 / 56 | Serif 400, −0.01em | Homepage statement only |
| `h1` | 36 / 44 | Serif 400 | Page titles (About, doc pages) |
| `h2` | 28 / 36 | Sans 500 or Serif 400 | Lead claim on Results; section titles |

### 6.3 Colour rules

- Ocean teal = brand + primary interaction. Amber = attention, rare (the running indicator; the lamp dot in the logo).
- Green = success only. Red = error only. Blue = information only.
- No accent colour is used decoratively. No near-duplicate shades: if a new value seems needed, reuse an existing token
  or change this document.
- TTA results are distinguished **structurally** (own column group and header), not by a colour.

## 7. Shape, borders, shadow, spacing

| Property | Rule |
|---|---|
| Radius | tags 5 px · controls and inputs 7 px · cards 10 px · image wells 12 px. **No pill-shaped controls.** Pills only for status. |
| Borders | 1 px `--border` (light) / `--ws-border` (dark), for structure only. No double, thick or decorative borders, no nested bordered boxes, no border around every section. |
| Shadow | None by default. Only for things that physically float: popovers, menus, tooltips, the swipe handle. Token `--pop-shadow: 0 1px 2px rgb(23 33 31/.06), 0 8px 24px rgb(23 33 31/.12)` (dark: `0 8px 24px rgb(0 0 0/.45)`). |
| Spacing scale | 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 96 px |
| Section rhythm | major sections 64–96 · related content 16–24 · control groups 8–12 |
| Cards | Only for genuinely independent objects (a dataset, an experiment, a content preview). Never for every paragraph, section, control group or metric. |

## 8. Overlay palette (image annotations)

Masks and boxes are the one place colour carries data. Hues are high-luminance and kept away from the water's
blue-green. Assign by class frequency (most common class gets colour 1). Never hard-code class names; read them from the
annotation file (see constitution).

**Default (20):**
`#FF7A6B` `#FFD25C` `#5CE1A0` `#FF9F43` `#C89BFF` `#FF86C8` `#B6F05A` `#6FD3FF` `#F25F8B` `#E8E06A`
`#9AA8FF` `#FFB3A0` `#4FE3E3` `#D7A6FF` `#FFC28A` `#A6F0C6` `#FF6FE0` `#F5F5A3` `#8FE36B` `#FFA8E0`

**Colour-blind preset (Okabe–Ito, lightened for dark water; cycles, so labels carry identity):**
`#F5A623` `#5DB8F0` `#2FC59A` `#F2E35C` `#4F9BE0` `#F07D3C` `#E58BC2` `#FFFFFF`

| Element | Spec |
|---|---|
| Mask | fill at 30 % opacity (user-adjustable 10–90 %), 1.5 px outline in class colour, 3.5 px dark halo `#0B1516` at 70 % under the outline |
| Box | 2 px stroke in class colour, no fill |
| Label | Inter 500, 13 px at 640-px image scale; class-colour fill, `#0B1516` text, 2 px radius; placed above the object, kept inside the image edges (flip below when near the top) |
| Label visibility | top 3 detections by score, plus whatever is hovered or isolated. Never all labels at once |
| Selection | hovering a class or instance dims everything else to 12 % opacity; the hovered mask gains +25 % fill and a 3 px outline |
| Ground truth | dashed outline (5/3), 25 % fill |
| Lab difference view | missed by variant: white dashed outline; found only by variant: white 3 px outline + 15 % white fill; found by both: neutral grey `#55595B` at 50 % |

**Correctness note:** detection (TOOD) and segmentation (SOLOv2) are separate heads. Boxes and masks are separate
predictions with their own scores and counts. Never pair a box with a mask as "one instance".

## 9. Components

Built on shadcn/ui, restyled until it no longer looks like shadcn. Each component communicates what it does, whether it
is active and whether it can be used — nothing more.

### 9.1 Buttons (three levels)

| Level | Look | Use |
|---|---|---|
| Primary | Solid `--ocean`, text `--on-ocean`, 7 px radius, 40 px high (44 on touch), Inter 500 14 px | The one primary action per view (Try your own image, Upload a photo) |
| Secondary | `--surface` fill, 1 px `--muted` border | Rare; a second real action (Download CSV) |
| Text | No fill, underline in `--muted` (offset 4 px), optional trailing → that nudges 2 px on hover | Everything else: Read the results, Hold to show ground truth, downloads in the inspector |

Small size: 32 px high (44 on touch). Press: `scale(.97)` over 120 ms. Hover only under `(hover:hover) and (pointer:fine)`.

### 9.2 Input

40 px high, 7 px radius, 1 px `--muted` border, `--surface` fill, placeholder `--text-2`. Focus: border `--ocean` plus a
1 px `--ocean` box-shadow (reads as a 2 px border). **No glow.**

### 9.3 Tabs (understated)

Text buttons, 24 px apart, a 1 px `--border` baseline; the active tab has a 2 px `--ocean` underline and `--text` colour;
inactive is `--text-2`. 40 px hit height (44 on touch). Used for: figure views (Chart / Table / Sources), the inspector's
view switch (Detection / Segmentation / Both), the Lab's compare modes, Explore filters. No pill tabs.

### 9.4 Badges — status only

5 px radius, 12 px Inter 500, 3 × 8 px padding, a 6 px dot in the status colour. Allowed: Ready, Processing (amber-soft
fill), Failed, Dataset, "No detectable difference" (null result). **Not** for labels like Model, Detection, Research,
test, val. Each badge has a word; never colour alone.

### 9.5 Tables (editorial)

No card around a table. Hairline row separators (`--border`); a 1 px `--text` rule under the header; column-group headers
with their own rule; 16 px horizontal cell gap (24 px between a numeric and a text column); numbers right-aligned in
tabular figures; bold only the winning or important value. Splits (test / val) are plain text in their own column. TTA
sits in its own column group, values in `--text-2`.

### 9.6 Source line

One quiet sentence under every table and figure, 13 px `--text-2`:
`Source: ab_vitl_acc_s3 · 3 seeds · JODD test split` followed by `Sources & data →`. Run and file IDs in mono; nothing
else in mono.

### 9.7 Footnotes

Inline superscript numeral in `--ocean`, 0.7 em. Provenance appears on hover, focus or tap in a popover (10 px radius,
`--pop-shadow`, 280 px wide): a bold one-line summary, then run IDs in mono. Below 560 px the popover docks to the
bottom of the viewport (16 px inset). Popovers are removed from layout when closed (`display:none`), so they never cause
horizontal scroll. A short notes list may repeat the summaries under the paragraph. Use sparingly — one marker per
claim, not per number.

### 9.8 Nulls and pending

A null result is a result: show the "No detectable difference" badge, never a blank cell. Values not yet exported show
as a dashed-underline placeholder (`.ph`). Pending variants stay visible and disabled, with what they need
("Pending ablation").

### 9.9 Collapsible

Summary row 40 px, Inter 500 14 px, a chevron at the end that rotates 180°. Opens with height + opacity
(`::details-content`, 220 ms) where supported; snaps elsewhere.

### 9.10 Slider, switch

Native range input with `accent-color: --ocean`, 24 px high (40 on touch); label row shows the value in tabular figures.
Switch: 32 × 18 track in `--muted`, `--ocean` when on.

### 9.11 Swipe comparison

Full-height 2 px `--ws-text` divider with a 34 px circular handle (`--ws-text` fill, ‹ › chevrons in `--ws-bg`, small
shadow). The whole image is a transparent range input, so drag, touch and arrow keys all work. Captions "Image" /
"Model output" (or variant names) top-left and top-right, Inter 500 12 px on `rgb(11 21 22/.7)`.

### 9.12 Charts

Clean and research-oriented: direct labels, clear axis, restrained grid in `--border`, consistent units, no legend when
direct labels suffice, no gradients, 3D or glow. Series are distinguished by **shape and colour** (boxes: circles in
`--ocean`; masks: diamonds in `--text`). Captions describe by shape, never by colour alone.

### 9.13 Navigation

`SeaBed Lens` wordmark (Inter 600, 15 px, with the lens mark whose small dot is amber) · Explore · Try it · Results ·
About, and on the right GitHub · Thesis. Links in `--text-2`; the current page in `--text` with a 2 px `--ocean`
underline. Below 760 px container width the links collapse to a "Menu" text button. The Component Lab and any style
guide are **not** in the public nav.

### 9.14 Image well

Neutral `--well`, 12 px radius (10 in compact grids, 7 for thumbnails, 50 % for sample dots), 4:3, `isolation:isolate`.
Canvas for the image, an SVG layer for overlays. While a run is in progress, the overlay dims to 30 %.

## 12. Motion

Motion reports a state change and never delays a scientific interaction. Animate `transform` and `opacity` only.

Tokens: `--ease-out: cubic-bezier(0.23,1,0.32,1)` · `--ease-drawer: cubic-bezier(0.32,0.72,0,1)` ·
`--d-press: 120ms` · `--d-micro: 160ms` · `--d-ui: 220ms` · `--d-sheet: 360ms`.

| Moment | Purpose | Motion |
|---|---|---|
| Run status pill (Try it) | Prevent a jarring change at the peak moment | Fade in + lift 4 px over 160 ms via `@starting-style`; fade out over 120 ms |
| Result arrives | State change | Overlay fades in over 220 ms; old result stays dimmed at 30 % while running |
| Sample image changes | Prevent a jarring change | New image crossfades over the old over 220 ms, in step with its overlay; opacity only |
| Add variant menu | Spatial: came from its trigger | Scale from 0.97 at top-left + fade, 150 ms |
| Collapsibles | State | Height + opacity over 220 ms (`::details-content`); snaps where unsupported |
| File dragged over Try it | Feedback | Overlay fades in over 150 ms |
| Footnote popover | State | Fade + 2 px over 160 ms |
| Button press | Feedback | `scale(.97)` over 120 ms |
| Phone sheet | Spatial | Drawer curve, 360 ms |

**Deliberately still:** threshold and opacity sliders (data being read), hold-for-ground-truth (must be an instant cut —
the flicker is the point), hover linking between list and image, Lab compare-mode switches, figure tabs, theme switch.
No ambient motion, parallax, counting numbers, scroll-triggered effects, springs or bouncing.

`prefers-reduced-motion: reduce`: drop movement (transforms), shorten fades to ≤ 120 ms, stop the status pulse, disable
smooth scroll.

## 13. Accessibility

Target **WCAG 2.2 AA**. Accessibility is part of the visual design, not a separate pass.

- Contrast per §6.4; non-text boundaries ≥ 3:1.
- Targets ≥ 44 × 44 px on coarse pointers (24 × 24 minimum everywhere, WCAG 2.5.8).
- Visible focus on every interactive element: 2 px `--ocean` outline, 2 px offset. Never remove focus styles.
- State never by colour alone: hidden classes are dimmed **and** struck through with a hollow dot; badges carry words;
  chart series differ by shape.
- Semantic HTML: real `<button>`, `<a>`, `<table>`, `<details>`, landmarks, one `<h1>` per page.
- Keyboard: the swipe divider is a range input (arrow keys); hold-for-ground-truth works with Space/Enter held; tabs use
  arrow keys (shadcn Tabs); class list items are buttons with `aria-pressed`.
- Images: every image well has a text alternative describing the scene and the counts; decorative canvases are
  `aria-hidden` with the description on the container.
- Live regions: run status is `role="status"`; result counts update politely.
- Reduced motion per §12. Test with axe-core in CI and a manual keyboard + VoiceOver pass per page.

- Sentence case everywhere. Plain words; no "AI-powered", "revolutionary", "unlock", sparkles.
- Headlines on Results state the finding as a sentence.
- Every number comes from `site_data.json` (see constitution, Article I) and carries its provenance via a source line or
  footnote.
- "test" and "val" are always written out; TTA is always "with flip TTA (test-time augmentation)" on first mention.
- Ablations that changed nothing say "No detectable difference".
- Describe the model as built (B0: colour stems, convex fusion, no DAPFT), not as in the proposal-era abstract.

## 15. Build mapping (tokens for `globals.css`)

Tailwind v4 + shadcn. Teal maps to shadcn's `--primary`. Workspace layouts wrap in `.ws`, which remaps the same variables
so components need no variants.

```css
/* frontend/app/globals.css */
:root {             /* reading, light */
  --background:#F7F8F6; --foreground:#17211F; --card:#FFFFFF; --popover:#FFFFFF;
  --primary:#087E8B; --primary-foreground:#FFFFFF; --ring:#087E8B;
  --secondary:#EEF1F0; --muted:#EEF1F0; --muted-foreground:#66716D; --accent:#EEF1F0;
  --border:#D9DEDC; --input:#8A9591; --destructive:#C94B4B; --radius:7px;
  --warning:#E7A93B; --success:#23845B; --info:#3D7FC4; --chart-1:#087E8B; --chart-2:#17211F;
  --well:#17191B;
}
.dark, .ws {        /* reading dark and the fixed workspace share one palette */
  --background:#0B1516; --foreground:#E9EFED; --card:#101D1E; --popover:#101D1E;
  --primary:#55B8C0; --primary-foreground:#0B1516; --ring:#55B8C0;
  --secondary:#172526; --muted:#172526; --muted-foreground:#9AA8A5; --accent:#172526;
  --border:#263536; --input:#74827E; --warning:#EAB45D; --well:#17191B;
}
```

- **Fonts:** `next/font/google` — `Inter`, `Source_Serif_4` (with `opsz` axis), `JetBrains_Mono`; self-hosted at build
  time, no runtime calls to Google.
- **Strip from shadcn defaults:** card shadows, pill-shaped ToggleGroup, focus-ring glow, Badge on non-status labels,
  bordered Table wrapper.
- **Components used:** Tabs · Slider · Switch · Collapsible · Drawer (phone) · DropdownMenu (Add variant) · HoverCard /
  Popover (footnotes) · Table + TanStack Table · Sonner (errors only).
- **Canvas:** image on `<canvas>`; masks and boxes on an SVG layer whose paths carry instance ids that drive hover in both
  directions; filters re-render on the client.
